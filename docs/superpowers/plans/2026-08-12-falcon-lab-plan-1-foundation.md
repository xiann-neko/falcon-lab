# Falcon Lab — Plan 1: Foundation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bootstrap the Falcon Lab Vite + React + TypeScript project with Tailwind CSS brand theming, IndexedDB persistence via Dexie, a React Router navigation shell (desktop sidebar + mobile tab bar), and GitHub Actions auto-deploy to GitHub Pages.

**Architecture:** A Vite-bundled React SPA with TypeScript. Dexie.js wraps IndexedDB for type-safe persistent storage of progress, quiz history, and spaced repetition state. React Router v6 handles client-side routing. Tailwind CSS with custom brand tokens delivers the dark UI. The navigation shell renders placeholder pages for all seven sections; every later plan fills them in.

**Tech Stack:** Vite 5 · React 18 · TypeScript 5 · Tailwind CSS 3 · React Router v6 · Dexie.js 3 · Vitest · @testing-library/react · @testing-library/user-event · fake-indexeddb

## Global Constraints

- Dark mode only: background `#0F1923`, accent `#E01B2D`, text `#FFFFFF`
- No server, no backend, no external API calls in this plan
- Responsive breakpoint at `md` (768 px): desktop sidebar visible above, bottom tab bar visible below
- GitHub Pages base URL: `/falcon-lab/` — Vite `base` option must be set to `/falcon-lab/`
- Node ≥ 18 required
- All tests run with `npm test`
- Dev server runs with `npm run dev`
- Repo: `xiann-neko/falcon-lab` on GitHub; deploy target: `https://xiann-neko.github.io/falcon-lab/`

- [ ] **Step 3: Create src/db/schema.ts**

```typescript
import Dexie, { type Table } from 'dexie'

// ── Enums ─────────────────────────────────────────────────────────────────────

export enum CompetencyLevel {
  Novice       = 'novice',
  Aware        = 'aware',
  Practitioner = 'practitioner',
  SME          = 'sme',
}

// ── Table row types ───────────────────────────────────────────────────────────

export interface CompetencyRecord {
  moduleId:       string           // primary key
  level:          CompetencyLevel
  quizScore:      number | null    // 0–100
  challengeScore: number | null    // 0–100
  scenarioScore:  number | null    // 0–100
  updatedAt:      string           // ISO date string
}

export interface QuizHistoryEntry {
  id?:            number           // auto-increment primary key
  moduleId:       string           // indexed
  questionId:     string           // indexed
  selectedAnswer: number           // 0-indexed answer choice
  isCorrect:      boolean
  answeredAt:     string           // ISO date string, indexed
}

export interface ScenarioDecision {
  stepId:      string
  choiceIndex: number
  isCorrect:   boolean
}

export interface ScenarioHistoryEntry {
  id?:         number              // auto-increment primary key
  scenarioId:  string             // indexed
  decisions:   ScenarioDecision[]
  finalScore:  number             // 0–100
  completedAt: string             // ISO date string, indexed
}

export interface SpacedRepetitionItem {
  id?:        number              // auto-increment primary key
  questionId: string             // indexed
  moduleId:   string             // indexed
  dueDate:    string             // ISO date string, indexed — used for due-date range queries
  retryCount: number             // 0 → 1 → 2 → retired after 3rd correct retry
}

export interface AppStateEntry {
  key:   string  // primary key, e.g. 'currentModuleId', 'currentTrackId'
  value: string
}

// ── Dexie subclass ─────────────────────────────────────────────────────────────

export class FalconLabDB extends Dexie {
  competency!:       Table<CompetencyRecord,      string>
  quizHistory!:      Table<QuizHistoryEntry,      number>
  scenarioHistory!:  Table<ScenarioHistoryEntry,  number>
  spacedRepetition!: Table<SpacedRepetitionItem,  number>
  appState!:         Table<AppStateEntry,         string>

  constructor() {
    super('FalconLabDB')

    this.version(1).stores({
      // Format: 'primaryKey, index1, index2, ...'
      competency:       'moduleId',
      quizHistory:      '++id, moduleId, questionId, answeredAt',
      scenarioHistory:  '++id, scenarioId, completedAt',
      spacedRepetition: '++id, questionId, moduleId, dueDate',
      appState:         'key',
    })
  }
}
```

- [ ] **Step 1: Create the GitHub Actions workflow**

Create `.github/workflows/deploy.yml`:
```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:      # also allows manual trigger from GitHub UI

permissions:
  contents: read
  pages: write
  id-token: write

# Only one deployment runs at a time; cancel in-progress if a new push arrives
concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Node.js 20
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run tests
        run: npm test

      - name: Build
        run: npm run build

      - name: Upload Pages artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: dist

  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    needs: build
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

- [ ] **Step 2: Create public/404.html for client-side routing on GitHub Pages**

GitHub Pages returns its own 404 page for any URL that doesn't map to a file. This breaks React Router deep links. The standard workaround is a custom 404 page that redirects back to the app root with the path encoded as a hash fragment, which `index.html` then picks up.

Create `public/404.html`:
```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8" />
  <title>Falcon Lab</title>
  <script>
    // Encode the path so GitHub Pages 404 redirects back to the SPA.
    // The app reads the hash on load and replaces it with the real path.
    var path = window.location.pathname.replace('/falcon-lab', '') || '/';
    window.location.replace('/falcon-lab/?r=' + encodeURIComponent(path));
  </script>
</head>
<body></body>
</html>
```

- [ ] **Step 3: Handle the redirect in index.html**

Open `index.html` and add this script block inside `<head>`, before any other scripts:
```html
<script>
  // Restore the original path after a GitHub Pages 404 redirect
  (function() {
    var redirect = new URLSearchParams(window.location.search).get('r');
    if (redirect) {
      var cleanUrl = window.location.origin + '/falcon-lab' + decodeURIComponent(redirect);
      window.history.replaceState(null, '', cleanUrl);
    }
  })();
</script>
```
